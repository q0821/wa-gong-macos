# 快速鍵綁定鍵盤裝置 Spec

狀態：功能實作與自動化驗證完成，內建、USB 與藍牙鍵盤完整實機驗收待進行
建立日期：2026-08-28
目標版本：`1.1.0` 候選功能

實作計畫：[DEVICE_BOUND_SHORTCUTS_IMPLEMENTATION_PLAN.md](./DEVICE_BOUND_SHORTCUTS_IMPLEMENTATION_PLAN.md)

## 摘要

Wa-Gong 目前以單一全域快速鍵設定處理所有鍵盤。不同鍵盤可能具有不同按鍵配置、左右修飾鍵位置或韌體對映，造成同一組快速鍵不適合所有裝置。

本功能允許每個可設定的快速鍵個別指定適用鍵盤。既有設定預設維持「所有鍵盤」，使用者也可為同一動作增加一筆或多筆裝置專用快速鍵。

## 使用者問題

- MacBook 內建鍵盤與外接鍵盤的按鍵配置不同。
- USB 與藍牙鍵盤可能交換 `Command`、`Option`、`Fn` 或其他按鍵位置。
- 同一組實體按鍵在不同鍵盤上不一定適合作為相同快速鍵。
- 使用者目前只能設定一組全域按鍵，切換鍵盤時必須反覆修改。

## 目標

- 每筆快速鍵可選擇「所有鍵盤」或一把指定鍵盤。
- 同一動作可同時擁有全域快速鍵與多筆裝置專用快速鍵。
- 既有快速鍵無痛遷移，升級後仍立即可用。
- 裝置斷線、重新連線或重新啟動 App 後，綁定仍能正確恢復。
- 不收集、不上傳鍵盤輸入內容或裝置識別資訊。
- 不影響中鍵錄音與既有錄音模式行為。

## Non-scope

- 不負責藍牙配對、連線或移除裝置。
- 不支援滑鼠、耳機、簡報器、遊戲控制器或任意藍牙裝置，只處理 HID 鍵盤。
- 不提供按鍵重新對映功能。
- 不自動轉換 ANSI、ISO、JIS 或不同語言鍵盤配置。
- 不建立整套鍵盤設定檔，也不因裝置切換整組設定。
- 不新增依 App、網站或模式自動切換的裝置規則。
- 不將裝置綁定同步至 iCloud 或其他外部服務。
- 不新增第三方套件。
- 不順手重構與快速鍵來源辨識無關的錄音、轉錄或貼上流程。
- 不負責驗證所有藍牙鍵盤韌體的相容性，休眠、喚醒與重新連線仍須依實際硬體測試。

## 使用者故事

### 裝置專用快速鍵

身為同時使用內建鍵盤與 USB 鍵盤的使用者，我希望替同一個錄音動作設定不同快速鍵，讓我不必在切換鍵盤後修改設定。

### 全域相容

身為只使用一把鍵盤的既有使用者，我希望升級後原本的快速鍵繼續適用所有鍵盤，不需要重新設定或授權新功能。

### 裝置離線

身為偶爾使用外接鍵盤的使用者，我希望鍵盤未連線時設定仍被保留，重新連線後可繼續使用。

## 核心行為

### 綁定範圍

每筆快速鍵包含一個範圍：

- `allKeyboards`：來自任何鍵盤的符合事件都可觸發。
- `device`：只有來自指定鍵盤的符合事件可觸發。

每個 `ShortcutAction` 可具有：

- 最多一筆 `allKeyboards` 綁定。
- 每把鍵盤最多一筆 `device` 綁定。
- 不限制不同鍵盤使用不同按鍵觸發同一動作。

### 比對優先順序

收到鍵盤事件時依下列順序處理：

1. 先比對該鍵盤的裝置專用綁定。
2. 沒有符合的裝置專用綁定時，再比對「所有鍵盤」綁定。
3. 同一動作的裝置專用綁定優先於全域綁定，單次按鍵不得重複觸發。
4. 不同動作若在相同裝置範圍內使用相同按鍵，視為衝突並拒絕儲存。

### 衝突規則

- 兩筆指定不同鍵盤的相同按鍵不衝突。
- 指定鍵盤的按鍵與另一動作的「所有鍵盤」相同時會衝突，因為兩者適用範圍重疊。
- 同一動作可讓裝置專用綁定覆蓋自己的全域綁定，不視為衝突。
- macOS 保留快速鍵與錄音浮窗保留快速鍵仍沿用現有驗證規則。
- 修飾鍵單鍵、一般組合鍵與功能鍵仍沿用 `ShortcutValidator` 的既有限制。

### 裝置斷線與重新連線

- 已儲存但未連線的裝置顯示「未連線」，設定不得自動刪除。
- 裝置重新連線且識別資訊相符時，自動恢復綁定。
- 裝置未連線時，該裝置專用快速鍵不觸發，也不自動退回其他裝置專用設定。
- 若同一動作另有「所有鍵盤」綁定，其他鍵盤仍可使用全域快速鍵。

### 無法唯一識別的鍵盤

部分鍵盤不提供序號，多把相同型號鍵盤可能只能取得相同的 Vendor ID、Product ID、Transport 與產品名稱。

- 無法取得穩定唯一識別資訊時，綁定套用到所有相同型號鍵盤。
- 介面顯示：「此型號無法個別辨識，設定會套用到所有相同型號鍵盤。」
- 不使用 USB 插孔的 `LocationID` 作為唯一永久識別，避免換插孔後綁定失效。

## 技術限制與決策

### 為何不能只沿用 `CGEvent`

目前 `ShortcutMonitor` 使用 `CGEventTap`，可取得虛擬鍵碼、修飾鍵與鍵盤類型，但公開 API 沒有提供實體鍵盤識別資訊。`NSEvent.deviceID` 的公開定義只適用繪圖板相關事件，不能用來辨識鍵盤。

因此不可用 `CGEvent` 的時間戳記或鍵盤類型猜測來源裝置，這在多把鍵盤同時輸入時會產生錯誤。

### 建議架構

新增單一 `KeyboardDeviceMonitor`，使用 macOS 內建 `IOHIDManager`：

- 只比對 Generic Desktop Keyboard 與 Keyboard or Keypad usage page。
- 監聽裝置加入、移除與輸入值 callback。
- 從 `IOHIDValue` 取得 `IOHIDElement`，再取得事件所屬 `IOHIDDevice`。
- 保留 HID 來源裝置與 macOS 最終 `CGEvent` 快速鍵語意，不以固定 HID usage 對照覆蓋系統的每部鍵盤修飾鍵設定。
- 在有界時間窗口內，依事件順序、按下或放開狀態與可用鍵碼線索配對 HID 來源和 `CGEventTap`。
- 每把鍵盤分別維護配對與按下狀態，避免跨裝置混用狀態。
- 只把符合已設定快速鍵的事件送到主執行緒，不保存一般輸入內容。

現有 `CGEventTap` 保留以下責任：

- 處理未啟用裝置綁定時的既有全域快速鍵。
- 在可可靠對應的情況下抑制已觸發的快速鍵事件。
- 維持目前 Accessibility 權限下的相容行為。

不得以「最近一筆 HID 事件」與 `CGEvent` 做無上限時間關聯。只有在短時間窗口內唯一配對成功時才可套用裝置綁定，配對不明確時必須安全地不觸發。若裝置專用事件抑制無法可靠完成，第一版允許觸發動作但不攔截原始按鍵，並在可行性驗證結果中明確記錄。

## Phase 0：技術可行性驗證

正式實作前先建立可丟棄的最小原型，驗證：

- 能列出 MacBook 內建鍵盤、USB 鍵盤與藍牙鍵盤；藍牙需另驗證本次連線的事件來源。
- Input Value callback 能提供正確的來源裝置。
- 左右 `Command`、`Option`、`Control`、`Shift` 與 `Fn` 可正確分辨。
- 一般按鍵、功能鍵與修飾鍵單鍵可與現有 `Shortcut` 表示可靠配對。
- 藍牙鍵盤休眠、喚醒、斷線與重新連線後識別值是否穩定，列為實際硬體相容性測試項目。
- 同時操作兩把鍵盤時，修飾鍵狀態不會互相污染。
- 已簽署 Release Build 能取得必要的輸入監控權限。
- HID callback 與 `CGEventTap` 的事件順序是否足以安全抑制按鍵。

Go 或 No-go 條件：

- 若無法穩定辨識事件來源裝置，本功能不得進入正式實作。
- 若只能穩定觸發但不能抑制按鍵，可進入實作，但介面與發行說明必須揭露限制。
- 第一版以內建鍵盤與 USB 鍵盤通過來源辨識、配對與安全降級作為 Go 條件。
- 藍牙鍵盤必須完成本次連線驗證後才能錄製；若重新連線識別不穩定，必須調整識別策略，不得用短暫 session ID 永久儲存。

## 資料模型

建議新增下列值型別，實際命名可在實作計畫中微調：

```swift
struct ShortcutBinding: Codable, Equatable, Identifiable {
    let id: UUID
    var shortcut: Shortcut
    var scope: KeyboardScope
}

enum KeyboardScope: Codable, Equatable {
    case allKeyboards
    case device(KeyboardDeviceReference)
}

struct KeyboardDeviceReference: Codable, Equatable, Hashable {
    let fingerprint: String
    let vendorID: Int?
    let productID: Int?
    let transport: String?
    let displayName: String
    let matchStrength: MatchStrength
}
```

### 裝置指紋

穩定識別資訊優先順序：

1. Vendor ID、Product ID 與裝置序號。
2. Vendor ID、Product ID、Transport 與產品名稱。
3. 系統內建鍵盤使用明確的 `builtInKeyboard` 類型，不依賴顯示名稱。

儲存規則：

- 永久儲存不可逆的本機指紋，不儲存原始序號。
- `displayName` 只供介面辨識，不參與唯一比對。
- 不將指紋、序號、按鍵內容或完整裝置清單寫入日誌。
- 若只能比對型號，`matchStrength` 必須為 `modelFamily`，介面同步顯示限制。

### 儲存位置與遷移

- 沿用 `UserDefaults`，不新增 SwiftData schema 或資料庫 migration。
- 新增版本化儲存鍵，例如 `ShortcutBindings_v1_<action>`。
- 既有 `Shortcut_<action>` 自動遷移為一筆 `allKeyboards` 綁定。
- 已清除的快速鍵仍保持清除，不得因 migration 重新出現。
- migration 必須可重複執行，成功寫入新格式後才標記完成。
- 在至少一個公開版本期間保留舊格式唯讀回退能力。

## 設定介面

目前快速鍵設定列保留既有錄製按鈕，新增裝置範圍選單。

### 預設顯示

- 既有快速鍵右側顯示「所有鍵盤」。
- 裝置專用快速鍵顯示產品名稱與連線狀態，例如「MX Keys Mini」或「MX Keys Mini，未連線」。
- 不使用 Emoji 表示裝置或狀態。

### 新增裝置專用快速鍵

每個可設定動作提供「新增裝置專用快速鍵」：

1. 選擇目前已連線或先前儲存的鍵盤。
2. 若選擇藍牙鍵盤，先提示使用者在該鍵盤按下一個字母鍵，驗證本次連線的事件來源。
3. 驗證只接受所選裝置的即時來源 ID，其他鍵盤與重複按鍵不得完成驗證。
4. 進入錄製狀態，提示「請在『裝置名稱』上按下快速鍵」。
5. 其他鍵盤輸入不得被錄入。
6. 通過裝置範圍衝突驗證後儲存。

藍牙驗證只對目前連線工作階段有效。鍵盤重新連線後，既有綁定仍依穩定裝置識別恢復；若要修改設定，必須重新驗證新的即時來源 ID。

### 編輯與刪除

- 使用者可重新錄製按鍵、變更指定鍵盤或刪除單筆綁定。
- 刪除裝置專用綁定不得影響同一動作的全域綁定。
- 移除鍵盤裝置紀錄前須顯示受影響的快速鍵數量。
- 全域快速鍵維持既有重設與清除行為。

### 權限提示

- 只有使用者首次新增裝置專用快速鍵時才請求「輸入監控」權限。
- 只使用「所有鍵盤」的既有使用者不應因升級被迫看到新權限提示。
- 權限被拒絕時保留設定，但裝置專用快速鍵停用，並顯示可操作的「開啟系統設定」。
- 權限說明使用繁體中文，清楚說明 Wa-Gong 只在本機比對快速鍵，不保存或傳送一般鍵盤輸入。

## 執行期解析

新增 `ShortcutBindingResolver`，輸入為：

- `ShortcutAction` 與所有綁定。
- 來源鍵盤指紋。
- 鍵碼、修飾鍵、事件種類與時間。

輸出為零或一個應觸發的 `ShortcutAction`。Resolver 必須是無 UI、可單元測試的純邏輯元件。

為避免熱路徑逐筆掃描，啟動監聽時建立索引：

```text
裝置指紋或 allKeyboards
  → 鍵碼與修飾鍵簽章
    → ShortcutAction
```

裝置加入、移除或設定變更時才重建索引。

## 錯誤與降級行為

- `IOHIDManager` 無法啟動：全域快速鍵繼續使用，裝置專用快速鍵停用並顯示原因。
- 輸入監控權限未知：顯示授權說明，不自動反覆彈出系統提示。
- 輸入監控權限被拒絕：不嘗試繞過權限，不把裝置綁定當成所有鍵盤綁定。
- 裝置名稱缺失：顯示「未命名鍵盤」加上非敏感的型號資訊。
- 裝置識別衝突：降級為同型號鍵盤範圍並告知使用者。
- Event Tap 中斷：沿用現有重設按下狀態邏輯，HID 層也必須清除每把裝置的按下狀態。

## 隱私與安全性

- 所有裝置偵測與快速鍵比對均在本機完成。
- 不建立網路請求，不把裝置資訊加入分析或錯誤回報。
- 不保存一般文字鍵輸入、按鍵歷史或輸入時間序列。
- 日誌只允許記錄監聽啟動成功、權限狀態與綁定數量，不記錄鍵碼、修飾鍵、產品序號或裝置指紋。
- callback 只處理鍵盤相關 usage，忽略其他 HID 裝置。
- 權限不足時採停用裝置專用功能的保守行為。

## 效能與生命週期

- App 全程只建立一個 `IOHIDManager`。
- HID callback 在專用序列佇列執行，不在 callback 做磁碟 I/O、UserDefaults 寫入或 UI 更新。
- 只有符合候選快速鍵的事件才送到 Main Actor。
- 裝置移除、App 結束與監聽重啟時必須取消 callback 並清除按鍵狀態。
- 目標是每筆 HID 事件只進行常數時間索引查詢，不掃描所有模式或全部快速鍵。

## 無障礙與在地化

- 裝置選單、連線狀態、權限錯誤與衝突訊息均需加入 String Catalog。
- 繁體中文使用台灣慣用語，例如「鍵盤」「藍牙」「輸入監控」「未連線」。
- VoiceOver 必須讀出快速鍵、指定裝置與連線狀態。
- 不只用顏色區分已連線、未連線或權限錯誤。
- 鍵盤操作可完成新增、錄製、變更裝置與刪除綁定。

## 驗收條件

- 既有快速鍵升級後全部維持「所有鍵盤」並可正常觸發。
- 同一動作可在內建鍵盤與 USB 鍵盤設定不同快速鍵。
- 在內建鍵盤按下 USB 鍵盤專用快速鍵不會觸發。
- 相同按鍵可分別綁定到兩把不同鍵盤的不同動作。
- 全域綁定與重疊裝置綁定發生衝突時，介面拒絕儲存並指出衝突動作。
- 鍵盤斷線後設定保留，重新連線後無須重設即可使用。
- 權限被拒絕時，全域快速鍵不受影響，裝置專用快速鍵不會誤觸發。
- 日誌與 UserDefaults 不包含原始裝置序號或一般按鍵歷史。
- 內建鍵盤與至少一把 USB 鍵盤完成實機驗證。
- 藍牙鍵盤可被選取，但建立或修改綁定前必須完成本次連線的按鍵來源驗證。
- 藍牙鍵盤驗證期間，其他鍵盤輸入不得完成驗證或被攔截。
- 藍牙鍵盤的休眠、喚醒與重新連線列入實際硬體相容性測試。

## 測試計畫

### 單元測試

- 舊格式 migration 產生 `allKeyboards` 綁定。
- 已清除設定不會因 migration 復原。
- migration 重複執行不會增加重複綁定。
- 裝置專用綁定優先於同一動作的全域綁定。
- 不同裝置上的相同按鍵不衝突。
- 全域範圍與任一裝置範圍重疊時正確判定衝突。
- 多把鍵盤的修飾鍵狀態完全分離。
- 裝置離線不會刪除或改寫綁定。
- 權限不足時 Resolver 不把裝置專用設定降級成全域。
- 裝置指紋不包含原始序號。

### 整合測試

- `IOHIDManager` 裝置加入與移除 callback 更新清單。
- 錄製器只接受所選鍵盤輸入。
- 快速鍵設定變更後，監聽索引即時刷新且不需重啟 App。
- `CGEventTap` 與 HID 監聽不會造成單次按鍵重複觸發。
- Event Tap 或 HID callback 重啟後不殘留按下狀態。

### 實機測試

- MacBook 內建鍵盤。
- USB 鍵盤。
- 藍牙鍵盤的本次連線驗證、休眠、喚醒、斷線與重新連線。
