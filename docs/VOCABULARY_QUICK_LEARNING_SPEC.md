# 自訂詞彙快速加入與修正規格

日期：2026-10-21。範圍已由使用者確認：「先做這兩項」。

## 問題與目標

目前快速加入面板仍需手動重打，歷史結果沒有修正並記住的入口。本輪讓使用者在遇到專有名詞或錯誤時完成一次明確教學，不需預先整理整份詞庫。

## 範圍與不處理項目

- 選取文字後使用既有「快速加入字典」快捷鍵，預填單一詞彙，人工確認後才寫入。
- 從已完成的歷史結果開啟「修正並記住」，輸入目前用字與正確詞彙，預覽後修正該筆輸出，可記住詞彙及選擇固定替換。
- 不做背景監看、自動學習、全文擷取候選、雲端分析、跨 App 自動修改、重新辨識或自動貼回。
- 不修改資料模型、schema、Provider、辨識能力或 TEA；不安裝 App、不啟動測試宿主、不發布或推送。

## 流程一：選取文字快速加入

1. 只有使用者呼叫既有快捷鍵時，才從當下前景 App 的焦點元件讀取選取文字。
2. 在面板取得焦點前完成有逾時限制的 Accessibility 讀取。只讀選取文字，不讀整個欄位；不模擬複製，不使用剪貼簿、選單動作或 AppleScript fallback。
3. 只有合法的單一詞彙可預填：1～120 字元、最多 2,048 bytes、不含換行、控制字元或逗號。過長、多行等選取不截斷、不拆成多詞，保留空白輸入並說明原因。
4. 無權限、無選取、不支援、secure text field 或前景 App 已變更時，保留手動輸入並顯示狀態。不得自動要求新權限或保存擷取內容。
5. 面板按 Enter 才儲存，Escape／關閉即捨棄，沿用既有重複與容量驗證。

## 流程二：修正並記住

1. 已完成的歷史結果顯示「修正並記住」。修正對象是整理結果（若有），否則是本機處理後文字；原始辨識永遠保留。
2. 表單顯示來源文字、目前用字、正確詞彙、替換筆數及完整結果預覽。使用既有字界與 Unicode 比對，修正該輸出的全部符合片段，清楚顯示筆數，不做模糊猜測。
3. 「記住並啟用正確詞彙」預設開啟。「之後固定替換這個用字」預設關閉，需明確勾選，並提示可能影響其他句子。兩項互相獨立。
4. 詞彙只允許單一合法詞，固定替換沿用共同衝突、循環、鏈結及容量檢查。已存在的詞可重新啟用，不建立重複；已存在的相同替換可重用，衝突則拒絕。停用且含多個別名的既有規則須先到字典整理，不從此入口重新啟用，避免連帶開啟未確認的其他別名。
5. 儲存前重新確認記錄仍存在、已完成、輸出與開啟時一致。過期／已刪除／處理中記錄拒絕寫入，保留表單錯誤。
6. 使用畫面所屬的 ModelContext，先確認沒有待存變更，再於同一個同步 MainActor 動作內檢查並一次 save，將本筆修正與使用者勾選的詞彙／規則共同保存。失敗 rollback；若已有其他編輯未存則拒絕操作，不回滾他人變更。過程沒有 await，不讓 autosave 插入中間狀態。
7. 成功後回到歷史顯示修正結果；不更動 rawTranscript、錄音、診斷、其他歷史或其他 App。取消不寫資料。

## 決策與理由

- 選擇 Accessibility 單次讀取，否決剪貼簿 fallback，因為快捷加入不應覆蓋使用者剪貼簿或擴大資料讀取。
- 選擇兩個短欄位與預覽，否決自動從整段編輯差異猜詞，因為中文人名與改寫邊界容易誤判；讓人工明確指定才可追溯。
- 選擇沿用 VocabularyWord 與 WordReplacement，否決新增候選詞 schema，因為這輪不做自動學習，不需要 migration。
- 保留已完成文字的編修與原始辨識，否決自動貼回，因為跨 App 交付需另外取得可靠焦點與內容一致性證據。
- 儲存採畫面既有 context 並要求無待存變更，否決另建 context 回寫同一筆歷史，因為畫面持有的物件可能無法即時反映另一 context 的改動。以同步單次 save 及 rollback 守住一致性，避免直接回滾共享 context 的其他編輯。

## 驗收條件

- 合法選取可預填，取消不寫入；拒絕空白、多行、控制字元、過長、逗號與 secure 元件。
- 修正只影響選定輸出層，原始辨識與另一層不變，數量及結果預覽一致。
- 預設只記住正確詞，不默默建立固定替換；未勾記住時不寫詞庫。
- 重複詞、停用詞、容量、規則衝突、狀態變更與不存在記錄均有行為測試。
- 建置與隔離測試通過，跨 App、Accessibility、VoiceOver 及完整互動另列人工待驗。
