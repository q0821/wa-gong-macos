- 記錄日期：2026-10-21。
- 狀態：已診斷，尚未修正；使用者先換模型比較，隨後要求收尾。

## 已取得的證據

1. 2026-10-20 23:46 與 23:47 的 App metadata 日誌顯示，`gemini-3.8-flash` 整理分別在 20.567 秒與 20.858 秒失敗，錯誤為 `VoiceInk.EnhancementError` code 7。以相同 Swift enum 的 NSError 橋接確認 code 7 為 timeout。
2. 前一筆 TEA 等待模型冷載入，轉錄總處理約 9 秒，後一筆約 2 秒；原生辨識分別為 1.400718 秒與 1.451634 秒。首次 native 載入約 14.206 秒，部分發生於錄音期間，不可將所有數值直接相加。
3. 使用者改用 Claude 後回報可回應，但其中一筆整理結果混入無標記英文自我說明，並自行判斷刪除部分原話。之後短句回報較正常，僅為使用者觀察，不構成問題已消失或品質驗收通過。
4. `AIPrompts.enhancementSystemTemplate` 已要求只輸出最終文字、不附解釋。`AIEnhancementOutputFilter` 只移除 thinking、think、reasoning XML 標記區塊，無法拒絕一般文字中的額外說明。離線執行實際過濾器，固定非私人示例的 `unmarked_commentary_passes_unchanged=true`。
5. 錄音後整理入口 `AIEnhancementService.makeRequest` 仍呼叫 SDK 的 `GeminiLLMClient`／`AnthropicLLMClient`。`NativeRefinementClient` 僅接到 `AIChatCompletionService.completeChat`，不能把聊天路徑的測試當成錄音整理路徑驗收。
6. App 的 Gemini／Anthropic 逾時自動重送已停用；SDK 遇逾時也直接失敗，但其共用 HTTP 層仍會在部分網路錯誤與 429／5xx 重送。未取得本次各 HTTP attempt 證據，不宣稱本次曾重送或重複計費。

## 判定與決策

確認 Gemini 整理逾時、部分 TEA 冷載入等待及輸出檢查不足。Gemini 為何未在期限內回應尚未確認，不能據此宣稱是 Google 服務故障，或只需更換模型即可修好。

先保留使用者目前模式與模型，不擅自延長逾時、不重送私人內容。否決單純拉長等待時間作為修復，因為它不處理輸出污染或請求路徑分歧，也不能保證降低延遲。
